📋 Evidence Standard E1–E7 — binding on every gate

Each rule maps to a specific review cycle this project lost. No gate passes on code inspection alone.

E1 — No gate passes on code inspection alone. Every gate requires an artifact from running something: log capture, test run, screenshot, measured number. "I read the diff and it looks right" is a review comment, not a gate pass. ← Round 5
E2 — Any log line that is gate evidence must be .info or higher. Logger.debug is not persisted by macOS and cannot be audited after the fact. ← Round 7
E3 — Thresholds are pre-registered before the run. Adjusted-after-seeing-results invalidates the gate and requires a re-run under the new number. ← W4 probe
E4 — Real-data fixtures. Gates run against General's actual message window from GRDB, not synthetic transcripts. ← Round 8
E5 — The author cannot sign their own gate. Implementer produces evidence; a second party verifies and signs. ← AgentDrop convention
E6 — Negative results are recorded, not discarded. A failed gate gets an artifact too; a gate that passed on the 4th attempt must show the 3 failures. ← Round 6b
E7 — Green suite means the whole suite, run concurrently. No cherry-picked runs. ← AgentDrop convention
Verdicts PASS · FAIL · PASS-WITH-CONCERNS (concern gets an owner + a later gate that re-tests it — stops rounding partial results up to PASS).
Artifact format One markdown file per gate at Docs/Reviews/optionb/<GATE-ID>-evidence.md — date/build/machine, operator + verifier (must differ, E5), pre-registered criteria (verbatim), method (reproducible), raw evidence, verdict, prior attempts (E6).
