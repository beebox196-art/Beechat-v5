## What changed in this round (Fable re-check fixes, 2026-08-05)

Fable's re-check identified **three real defects** in the engine and harness, and corrected my earlier (wrong) diagnosis. This round applies each fix and re-runs the gate.

**Fix 1 — `engineScrollTop` was set to the wrong quantity** (`transcript.html` lines 241, 247, 398, and `swapTopic` path). Previously `engineScrollTop = $scroller.scrollHeight`. Now `engineScrollTop = $scroller.scrollHeight - $scroller.clientHeight` (the clamped value, since `scrollTop` is browser-clamped). This fixes the inverted user-scroll detector: with scrollHeight stored, every engine repin appeared as a 680px mismatch vs the actual scrollTop, so the detector misclassified every engine repin as a user scroll. Tolerance also raised from 2px to 4px for sub-pixel/zoom rounding.

**Fix 2 — user intent has persistence.** Previously `userScrolledUp = false` was cleared unconditionally inside `_updatePinned` whenever `d < 50`. This made the flag oscillate true→false inside a single handler and was reliably false when `deferredRepin` read it. Now `userScrolledUp` is cleared ONLY by:
- the user's own scroll returning them to within the bottom band (d < 50),
- the jump-to-latest button (explicit re-pin),
- `pinToBottom()` (explicit re-pin), or
- `swapTopic()` (atomic pin-then-load).
Engine repins never clear `userScrolledUp` from inside `_updatePinned` — they go through the explicit re-pin path. This is the gating fix for criteria 5 and 9: the engine can now reliably detect and remember the user's scroll-up.

**Fix 3 — bounce probe decontaminated.** Previously the probe fired at t=11.5s while the 50 streaming appends (at 400ms intervals, running to t≈20s) were still firing, and each append's `stateAfterRepin()` call triggered `deferredRepin()`. The probe's "NO REPIN ISSUED" was true of the probe and false of the harness. Now the probe runs at **t=22s**, AFTER the streaming window completes (~2s margin). The probe's measurement of the engine's natural behaviour under the user's scroll-up is now uncontaminated.

**Fix 4 — `window.scrollTo` DOES fire a scroll event in WebKit; the probe's real defect was a listener-target bug (CORRECTED 2026-08-06, Fable super-check B-1).** The original write-up below concluded "`window.scrollTo` does NOT fire a scroll event in WebKit" and "the probe now explicitly dispatches a scroll event after `scrollTo`." The manual `dispatchEvent` workaround masked the defect rather than fixing it. Corrected fix: the engine now listens on `document` (not `$scroller`), and the probe/tests use a real `window.scrollTo` with no manual dispatch. The probe/tests fail before this correction and pass after — T2 is the regression guard. (Original text preserved below for the record.)

**Measurement-methodology fix (this round) — Swift polling was starving the page's rAFs.** The previous G2 harness used Swift-side polling at 16ms intervals to read `window.bc.__pendingStateAfterRepin`. The harness now uses a **FIFO callback queue** wired to a `g2State` message handler: the page posts the captured state to `g2State` when the post-repin microtask fires, and Swift dequeues the callback. This eliminates the polling-starvation race while preserving the existing post-repin measurement semantics.
